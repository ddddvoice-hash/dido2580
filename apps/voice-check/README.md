# 목소리 녹음 검사기

원본 WAV가 가이드 규격에 맞는지 파일마다 검사합니다. 외부 패키지 없이 Node만 씁니다. 파일은 읽기만 하고 고치지 않습니다.

## 쓰는 법

```
node apps/voice-check/check.js <폴더나 파일...> [--json out.json] [--csv out.csv]
```

- 폴더는 하위 폴더까지 훑습니다. WAV가 아닌 파일(mp3 등)은 "WAV 아님"으로 건너뜁니다.
- 종료 코드: 결과 파일(--json, --csv) 저장에 실패하면 2(반려가 있어도), 반려 코드가 하나라도 있으면 1, 읽기 실패만 있으면 2, 아니면 0.
- 테스트: `node apps/voice-check/test.js` (합성 WAV를 임시 폴더에 만들고 지웁니다)
- 원본 WAV와 검사 결과 파일은 저장소에 두지 마세요.

## 코드 뜻

반려 (하나라도 있으면 다시 녹음)

| 코드 | 뜻 |
|---|---|
| V02 | 찢어짐. 최대값이 -1 dBFS 이상 |
| V05 | 여백. 마지막 말소리 끝에서 파일 끝까지가 0.3초 미만 또는 1초 초과 |
| V08 | 가공 흔적. 한 채널에서 완전 0(샘플값 0)이 480샘플 이상 이어진 구간이 있음 (샘플레이트와 상관없이 480샘플 고정. 스테레오는 어느 채널이든 걸리면 반려) |

경고 (참고용)

| 코드 | 뜻 |
|---|---|
| FORMAT | 48000Hz, 24bit, 모노가 아님 (32bit float, 스테레오 포함) |
| PEAK | 최대값이 -6 ~ -3 dBFS 밖 |
| ROOM | 첫 말소리가 10.0초보다 앞 (앞 10초는 룸톤이어야 함) |
| NOISE | 앞 10초 평균 크기가 -60 dBFS보다 큼 |
| NAME | 이름이 `001_키_take01.wav` 형식(숫자 3자리, 키에 밑줄 가능, 대소문자 무시)이 아님 |
| TRUNC | data 청크 선언 크기가 0이거나 실제 파일보다 큼(녹음이 끊겼거나 헤더가 손상됨). 남은 길이만큼만 읽음 |
| TAIL_EDGE | 뒤 여백이 0.3초나 1.0초에서 0.02초 안쪽. 말소리 끝을 20ms 단위로 재서 판정이 흔들릴 수 있으니 귀로 확인 |
| NOSPEECH | 말소리를 찾지 못함 (V05는 판정하지 않음) |

화면에는 길이, 형식, 최대 dBFS, 앞 말소리 시작, 뒤 여백, 완전0 구간 수가 나옵니다. 말소리가 아닌 구간의 완전 0 비율(%)과 앞 10초 평균 크기도 함께 나옵니다.

## 한계

- 말소리 구간은 `apps/reading-coach/analysis.js`의 방식(20ms 프레임 크기, 녹음마다 잡는 기준)을 그대로 씁니다. 잡음이 크거나 말소리가 전체의 10% 미만이면 틀릴 수 있습니다.
- NOISE는 앞 10초 전체의 평균입니다. 말소리가 10초 안에 들어오면 NOISE도 같이 뜹니다(ROOM과 함께 보세요).
- 스테레오: 최대값(V02)과 완전 0(V08)은 채널별 원래 샘플로 판정합니다. 말소리 분석은 두 채널의 에너지를 합친 크기를 써서 반대 부호 소리가 상쇄되지 않습니다.
- V05 경계는 1e-6초 허용 오차로 비교합니다(정확히 0.3초, 1.0초는 통과).
- 16/24/32bit PCM과 32bit float만 읽습니다. 8bit, 64bit float, 압축 WAV, RF64(4GB 넘는 WAV)는 "읽기 실패"입니다. 녹음 한 파일이 4GB를 넘을 일이 없어 RF64는 범위 밖으로 뒀습니다.
- 헤더 검사: 샘플레이트 0, 채널 수, 블록 크기(채널 수 x 비트 수), EXTENSIBLE의 길이와 SubFormat GUID 전체를 확인합니다. 값이 이상하면 "읽기 실패"입니다. float 샘플에 NaN/Infinity가 있어도 읽기 실패입니다.
- CSV는 읽기 실패 사유를 `error` 칸에 따로 적습니다.
- 한 파일에 여러 줄이 이어진 긴 녹음은 마지막 말소리 뒤 여백만 V05로 봅니다.
- 샘플 전체를 Float32Array 하나로 올리므로 메모리는 샘플 수 x 4바이트 정도 씁니다(말소리 분석 때 프레임 값 복사본이 조금 더 듭니다). 48kHz 모노 한 시간이면 약 0.7GB, 두 시간이면 약 1.4GB입니다. 몇 시간짜리 긴 파일은 나눠서 검사해 주세요. 스트리밍 처리는 범위가 커서 하지 않았습니다.

## 대본 줄과 녹음 맞추기 (align.js)

```
node apps/voice-check/align.js <wav> <script.json> --csv <out.csv> [--min-pause 1.0]
```

- 대본은 `{"lines":[{"no","key","direction","text"}, ...]}` 형식 JSON입니다.
- 1초(`--min-pause`) 이상 쉬는 곳으로 말소리 덩어리를 나누고, 대본 순서대로 줄에 배정합니다. 덩어리 수와 줄 수가 다르면 줄의 한글 음절 수와 덩어리 길이 비율이 고르게 되도록 동적 계획법으로 맞춥니다.
- 대본 줄에 `"syllables": 숫자`를 넣으면 그 값을 음절 수로 씁니다(숫자·영문 줄용). 없으면 한글 음절을 셉니다(NFC로 정규화한 뒤 셈).
- CSV(UTF-8 BOM, 엑셀용) 칸: no, key, text, start_sec, end_sec, dur_sec, syllables, syl_per_sec, chunks, uncertain, reason.
- 불확실(uncertain=Y) 기준: 덩어리를 합친 줄, 덩어리를 쪼갠 줄, 초당 음절 수가 중간값의 0.5배 미만 또는 2배 초과, 앞뒤 줄과의 쉼이 1.2초 미만. 이유는 reason 칸에 적힙니다.
- 테스트: `node apps/voice-check/test-align.js`

한계
- 음성 인식을 하지 않습니다. 줄 내용이 맞는지는 모르고 순서와 길이 비율만 봅니다. 불확실 줄은 직접 들어 확인해 주세요.
- 덩어리가 줄보다 많으면 합치기만, 적으면 쪼개기만 합니다. 한 녹음에 두 경우가 섞이면 어긋날 수 있습니다.
- 한 덩어리를 나눈 줄의 경계는 앞에서부터 차례로 글자 수 비율로 추정합니다(안쪽 쉼이 가까우면 거기에 맞추되 쉼 하나는 한 번만 씀). 모든 줄은 길이가 양수이고 시간 순서가 이어지게 만들며, 어긋나면 불확실로 표시합니다.
- 헤더 검사는 check.js와 같은 함수를 씁니다.
- 음절 수는 한글만 셉니다. 숫자·영문은 세지 않습니다.

## 기준 프로필 (profile.js)

```
node apps/voice-check/profile.js <wav> [--json out.json]
```

- 한 녹음의 음높이(F0 중간값·평균·10/90 백분위·범위 반음), 초당 음절(추정), 쉼 길이 분포, 문장 끝 음높이(내림/평탄/올림), 크기(dBFS)를 표로 보여 줍니다.
- 말소리·쉼 구간은 `apps/reading-coach/analysis.js`(쉼은 0.25초 이상)를 그대로 씁니다.
- 문장 끝은 0.7초 이상 쉼 바로 앞 덩어리의 마지막 300ms F0 중간값과 덩어리 전체 F0 중간값을 비교합니다(±1반음 안이면 평탄).
- 크기는 dBFS입니다(LUFS 아님).
- 테스트: `node apps/voice-check/test-profile.js` (trim.js 테스트도 함께 돕니다)

한계
- 음절은 추정입니다. 대본이 없어 크기 곡선의 봉우리를 센 값이라 숫자와 영문, 연음, 속삭임에서 틀릴 수 있습니다. 비교용 상대값으로만 보세요.
- F0는 단순 자기상관(12kHz로 줄여 40ms 창, 60~500Hz)입니다. 옥타브 오류, 거친 목소리·잡음 구간의 오판이 있을 수 있어 중간값과 백분위로만 봅니다.
- 문장 끝 음높이는 "0.7초 이상 쉼 앞"을 문장 끝으로 간주합니다. 문장 중간의 긴 쉼도 세어집니다.

## 뒤 여백 자르기 (trim.js)

```
node apps/voice-check/trim.js <in.wav> <out.wav> [--tail 0.8]
```

- 마지막 말소리 끝 뒤 여백을 `--tail`초(기본 0.8, 0~1초만 허용)로 자른 사본을 만듭니다. 앞부분은 건드리지 않습니다.
- 헤더와 샘플은 바이트 그대로 복사하고 RIFF/data 크기 값만 고칩니다(다시 인코딩·정규화 없음). 입력 파일은 읽기만 합니다.
- 입력과 출력 경로가 같으면 거부합니다. 이미 여백이 더 짧으면 늘리지 않고 그대로 복사합니다.
- 한계: data 청크 뒤에 붙은 다른 청크(LIST 등)는 사본에 넣지 않습니다. 말소리 끝은 20ms 단위로 잡습니다. 사본에도 원본의 V08(완전 0 구간)은 그대로 남습니다.

## 새 녹음 한 번에 검사 (screen.js)

```
node apps/voice-check/screen.js <폴더> --ref <기준.wav> --work <_work 폴더> [--exclude-sha <파일>] [--json out.json] [--md out.md]
```

- 폴더(원본)는 읽기만 합니다(하위 폴더는 보지 않음). 쓰기는 `--work` 아래(`converted/`, `upload/`)와 `--json`/`--md` 경로뿐입니다. `--work`가 검사 폴더 안이면 거부합니다.
- 파일마다 이 순서로 봅니다: 이전에 제외(`--exclude-sha`: 한 줄에 해시 하나, `#` 주석 가능) -> 기준과 같은 해시 -> 같은 해시 묶음의 첫 파일(이름 순)만 남기고 나머지 중복 -> 이름 확인 -> 비WAV 변환 -> check.js·profile.js -> 섞임 의심 -> 톤 -> 판정.
- 이름 확인: 확장자를 뺀 이름에서 숫자·괄호·공백·밑줄·하이픈과 일반 단어(음성, 녹음, 샘플, 평소, 기본, 테스트, voice, rec, recording, sample, take, base, new, `001_키_take01` 형식)를 빼고 글자가 남으면 `대표 확인(이름)`으로 쓰지 않습니다. 이런 파일 이름은 md/json/화면 어디에도 쓰지 않고 `이름 가림 #1`로만 적습니다(해시 앞 8자리는 적음). converted/upload에도 넣지 않습니다.
- 비WAV(mp3, m4a, aac, flac, ogg, wma 등): ffmpeg가 PATH에 있으면 `converted/`에 24bit 모노 WAV 사본을 만들어 검사하고 `압축 원본`으로 표시합니다. 없으면 `압축 원본 · 변환 불가(ffmpeg 없음)`으로 표시하고 분량에서 뺍니다.
- 톤 다름: 기준과 음높이 중간값 차이가 3반음 초과.
- 섞임 의심(쓰지 않음), 둘 중 하나:
  - 배경: 말소리 밖 구간(파일 앞·뒤 0.5초 제외)의 20ms 프레임 RMS 중간값이 -50 dBFS보다 크고, 75% 이상 프레임이 -55 dBFS보다 큼.
  - 두 음높이: 유성 프레임 F0(반음)를 2-평균으로 나눴을 때 두 중심 차이 7반음 이상, 작은 무리 20% 이상, 두 중심 가운데 +-1반음의 밀도가 두 봉우리 모두의 25% 미만.
- 판정: 걸린 표시가 없을 때 반려 없음 `쓸 수 있음`, V05만 `뒤 여백 자르면 쓸 수 있음`, 그 밖 반려 `반려`. 표시가 걸리면 `쓰지 않음`.
- `upload/`: 쓸 수 있는 파일과 기준 파일의 사본을 파일별로 만듭니다(이어 붙이지 않음). 뒤 여백이 0.8초보다 길면 trim.js 방식으로 0.8초로 자르고, 0.8초 이하면 그대로 복사합니다. 사본에 check.js를 돌려 V05가 없는지 확인합니다. 이미 있는 파일은 지우지 않고 같은 이름이면 덮어씁니다.
- 합계는 쓸 수 있는 파일의 길이·말한 시간 합(기준 포함/미포함)과 10·20·30분 도달 여부입니다. 기준 파일은 판정과 상관없이 `기준 포함` 합계와 upload에 들어갑니다.
- 테스트: `node apps/voice-check/test-screen.js` (ffmpeg 유무는 주입해서 시험합니다)

한계
- 섞임 의심 기준(dBFS, 반음, 비율)은 고정값이라 목소리·환경에 따라 놓치거나 잘못 걸 수 있습니다. 의심 표시는 귀로 확인해 주세요.
- 파일마다 F0를 두 번 잰 만큼 느립니다(10분짜리 한 파일에 수십 초).
- 해시가 같은 파일만 중복으로 봅니다. 같은 소리를 다시 저장한 파일은 못 잡습니다.
