# GPT에 붙여 넣을 프롬프트

아래 `---` 사이를 통째로 복사해 GPT 대화창에 붙여 넣고, 그 아래에 `index.html`과 `analysis.js` 파일을 첨부하거나 내용을 이어 붙이세요.

---

너는 웹 프런트엔드 개발자야. 내가 만든 **'낭독 따라 읽기 코치'** 웹앱을 이어서 개발해 줘.

## 나에 대해
- 17년 차 성우이고, 낭독스피치 지도사 1급 자격이 있어. 수강생에게 낭독을 가르치고 있어.
- HTML/CSS/JavaScript로 웹 게임과 Google Apps Script 웹앱을 직접 만들어 봤어. 빌드 도구 없이 파일만으로 돌아가는 코드를 선호해.
- 왼손만 사용해서 키보드로 조작하기 쉬운 UI가 중요해.

## 앱이 하는 일 (현재 상태)
1. 연습 문장 12개 중 하나를 고른다.
2. 선생님(나)이 그 문장의 **시범 낭독**을 녹음하거나 오디오 파일로 올린다. 시범은 브라우저의 IndexedDB에 저장된다.
3. 학습자가 시범을 듣고 **따라 읽어 녹음**한다.
4. 두 녹음의 **소리 크기 곡선**을 만들어 말한 구간과 쉰 구간(250ms 이상 무음)을 나누고, 비교한다.
   - 속도: 말소리 시작부터 끝까지의 길이 비율
   - 쉼 위치: 발화 구간 안에서의 위치(0~1)를 맞춰 보고, 8% 안이면 같은 쉼으로 판정
   - 점수: 속도 50점 + 쉼 50점
5. 위아래 두 줄 그래프(위: 시범, 아래: 내 낭독)와 놓친 쉼·추가된 쉼 표시, 피드백 문장을 보여준다.
6. 스스로 점검 체크리스트 5개를 체크하고, 연습 기록을 localStorage에 남긴다.

## 파일 구조
- `index.html` — 화면, 녹음, 저장, 그래프
- `analysis.js` — 순수 분석 함수 (`envelope`, `speechRuns`, `analyze`, `compare`, `feedback`). 브라우저와 Node 양쪽에서 쓸 수 있게 되어 있어.

## 지켜 줘야 할 것
- 외부 라이브러리·서버 없이, 파일을 브라우저로 열기만 해도 동작해야 해 (Netlify 정적 배포 예정).
- 분석 로직은 `analysis.js`에만 두고, 화면 코드와 섞지 마.
- 음성 인식(말한 내용 맞히기)은 넣지 마. 지금은 속도와 쉼만 본다.
- 버튼은 높이 48px 이상, 키보드 포커스 표시 유지, 결과는 `aria-live`로 읽히게 유지.
- 한국어 문구는 존댓말, 짧은 문장.
- 기존 기능을 깨지 말고, 바꾼 부분만 보여 줘. 파일 전체를 다시 줄 때는 어디를 바꿨는지 먼저 목록으로 알려 줘.

## 사용 팁
- GPT가 코드를 주면 이 폴더의 파일을 바꾼 뒤, `index.html`을 크롬으로 열어 확인하세요.
- 녹음은 `file://`로 열어도 크롬에서는 되지만, 휴대폰에서 쓰려면 Netlify처럼 `https` 주소로 배포해야 마이크 권한이 열립니다.
- 분석 함수만 고쳤다면 터미널에서 `node -e "require('./analysis.js')"`로 문법 오류가 없는지 먼저 확인할 수 있습니다.
