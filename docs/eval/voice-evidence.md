# 목소리 관찰 근거표 (대표작 B) v2 · 성우 김디도

2026-10-05 · **v2**: GPT 아스트라(`gpt-6-astra`) R10 비판 12건과 G4 독립 초안을 반영해 클라우드 팀장이 다시 씀.
측정 방법의 자세한 설명은 G4(`docs/gpt/G4-voice-evidence.md`)가 더 정확해 그쪽을 기준으로 삼았어요(클라우드가 `profile.js`·`analysis.js` 코드와 대조해 확인: 쉼 최소 260ms, 문장 끝 후보에서 마지막 덩어리 제외, 덩어리 유효 프레임 10개·끝부분 3개 미만 제외).

## 원칙

1. **측정값은 근거이지 판정이 아니에요.** 따뜻한지는 사람이 기준표로 판단하고, 측정값은 그 판단 옆에 놓는 관찰 기록이에요. 점수로 바꾸지 않아요.
2. **목표값이 없어요.** 어떤 빠르기·쉼·음높이가 "맞다"고 정하지 않아요. 한국어 상담 문장에서 그런 값을 입증한 자료를 확인하지 못했어요.
3. **측정 불가는 측정 불가예요.** 말소리를 못 찾거나 값이 `null`이면 0점이나 "따뜻하지 않음"으로 바꾸지 않고, 그대로 적어요.
4. **사람이 먼저 듣고, 수치는 나중에 봐요.** 수치를 먼저 보면 판단이 끌려갈 수 있어요(가능성, 확인 안 됨).

## 항목: 재는 것과 못 재는 것

| 기준표 항목 | 이 도구가 재는 것 (실제 계산 이름) | 함께 들을 질문 | 못 재는 것 |
|---|---|---|---|
| `pace` 빠르기 | 초당 음절 **추정**(크기 봉우리 수 ÷ 검출된 말소리 시간) | 이 상황에서 듣는 사람이 따라올 수 있었나 | 실제 음절 수, 단어 단위 빠르기 |
| `pause` 쉼 | 260ms 이상 쉼의 개수·길이·위치(시각) | 중요한 말 앞에서 쉬었나(원고와 맞춰 사람이 확인) | 어느 낱말 앞의 쉼인지 |
| `ending` 말끝 | **긴 쉼 앞 끝부분 음높이 변화**(700ms 이상 쉼 앞 덩어리만, 마지막 덩어리는 제외) | 위로는 차분히 닫혔나, 질문은 열렸나 | 실제 문장 끝, 마지막 문장의 말끝 |
| `pitch` 음높이 | 유효 F0의 중간값(Hz)과 10~90 백분위 폭(반음), 유효 프레임 비율 | 단조롭거나 과장되게 들렸나 | 감정, 옥타브 오류가 없는지 |
| (기준표에 없음) 크기 | 전체·말소리 RMS(dBFS), 최대값 | 너무 크거나 작게 들렸나 | 시간에 따른 크기 안정(아직 계산 안 함) |
| `breath` 호흡·음색 | **재지 않음** | 숨소리·음색이 내용과 어울렸나 | 전부 사람 청취 |
| `congruence` 내용과의 일치 | **재지 않음** | 말투가 말의 내용과 맞았나 | 전부 사람 청취 |

## 참고 관찰값 (목표값 아님)

성우 김디도의 배리어프리 낭독 **속리산** 한 편(431.3초)을 `profile.js`로 잰 값이에요(게시판 '속리산 기준 프로필'). 같은 화자의 다른 낭독과 나란히 볼 때 쓰는 참고값이고, 상담 문장의 적정값이라는 근거는 없어요.

| 측정 | 관찰값 |
|---|---|
| 초당 음절 추정 | 5.91 |
| 쉼 | 172개(분당 24.0회), 길이 중간값 0.56초 |
| 긴 쉼 앞 끝부분 음높이 | 판정 79곳 중 내림 67·평탄 8·올림 4 |
| 음높이 | 중간값 142.5Hz, 폭 14.1반음 |
| 크기 | 말소리 −20.4 dBFS, 최대 −1.8 dBFS |

다시 재려면 같은 녹음 원본, 분석 구간, 코드 버전이 필요해요. 녹음 원본은 공개 저장소에 올리지 않아요.

## 상황 문항의 낭독 메모와 잇기

상황 문항(`docs/eval/scenarios-v0.json`)의 낭독 메모는 **낭독 지시**예요. 이 표로 "지시대로 됐다"를 자동 판정하지 않아요. 사람이 들은 판단 옆에 관련 수치를 함께 보여 줄 뿐이에요.

| 낭독 메모 예 | 옆에 놓을 수치 |
|---|---|
| "평소보다 조금 늦추고" | 초당 음절 추정(같은 화자의 다른 낭독과 비교) |
| "첫 문장 뒤 짧게 쉬기", "질문 뒤 기다리기" | 해당 시각의 쉼 길이(위치는 사람이 표시) |
| "말끝을 차분히 내리기", "끝을 살짝 올려 열어 두기" | 긴 쉼 앞 끝부분 음높이(마지막 문장은 못 잼) |
| "번호는 또렷하게, 천천히" | 아직 구간 측정이 없음(다음 과제) |

## 비교 시연 설계

같은 문장을 두 방식으로 읽은 녹음으로, 측정 근거와 사람의 청취 판단을 **연결하는 과정**을 보여 줘요.

1. **문장:** `voice/test-sentences.csv`의 상담 문장 B01~B05. 문장마다 대응 상황 문항 번호를 정해 적어요. CSV의 "확인할 점" 칸(기대 방향)은 평가자에게 보여 주지 않아요.
2. **녹음:** 같은 마이크·거리·입력 크기·후처리 없음. 낭독 A/B 순서와 조건을 기록하고, 익명 번호만 써요.
3. **듣기(먼저):** 평가자 2명 이상이 낭독 의도와 수치를 모르는 채로, 순서를 바꿔 가며 듣고 기준표 항목별 판단·이유·구간을 따로 적어요.
4. **수치(나중):** 측정값·단위·검출 실패·제외 수를 나란히 놓고, 다르게 들린 구간을 다시 들어요. 처음 판단과 다시 들은 판단을 구분해 남겨요.
5. **기록:** 관찰값 / 들은 구간 / 내용과의 관계 / 다른 설명 가능성 / 판정 또는 보류 이유. 평가자 의견이 갈리면 수치로 승자를 정하지 않아요.

**이 시연이 보여 줄 수 없는 것:** 두 낭독은 여러 특성이 함께 바뀌어서 어느 특성이 인상을 만들었는지 나눌 수 없어요. 한 화자·5문장·평가자 2명으로 보편적인 따뜻함 효과나 측정의 타당성을 입증하지 못해요(관계를 보려면 GPT Q4의 20문장 × 2방식 같은 별도 설계가 필요).

**공개할 것:** 맞은 사례와 안 맞은 사례, 검출 실패와 판단 보류 사례 모두.
