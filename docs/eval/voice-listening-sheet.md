# 목소리 비교 시연 청취 기록지 · 성우 김디도

2026-10-06 · GPT 아스트라(`gpt-6-astra`) G11 초안을 클라우드 팀장이 검토해 채택(원본: `docs/gpt/G11-listening-sheet.md`). 근거표 `docs/eval/voice-evidence.md` v3.1의 순서 1~3·재현 기록과 칸이 하나씩 맞는지 확인했어요. 표 2의 듣기 기준은 대표가 정한 `rubric.json` 원문이에요. 실제 청취에 써 본 적은 아직 없어요.

이 양식은 `docs/eval/voice-evidence.md` v3의 시연 순서 1~3과 재현 기록을 옮긴 초안이에요. 실제 청취 결과는 아직 없어요. 판단은 목소리가 내용에 맞게 들리는지에 한정하고, 수치를 점수나 정답으로 바꾸지 않아요.

## 작성 방법

- 평가자는 2명 이상으로 구성해요. 이름 대신 평가자 코드를 쓰고, 평가자마다 표 1~4를 따로 채워요. 첫 판단을 적는 동안 서로 이야기하지 않아요.
- 운영자는 낭독 의도·방식·테이크를 숨기고, 문장마다 무작위 익명 녹음 번호 두 개를 A와 B에 연결해요. A/B는 이 기록지의 고정 비교 표지이며 낭독 방식이나 실제 재생 차례를 뜻하지 않아요. 방식과 연결하는 정보는 평가자용 기록지에 쓰지 않아요.
- 표 1의 재생 순서는 듣기 전에 정해요. 표 1~2만 먼저 제공하고, 모든 평가자의 5문장 첫 판단이 확정된 뒤 표 3의 수치를 한꺼번에 공개해요. 참고 관찰값이나 원고의 점검용 메모는 정답처럼 보여 주지 않아요.
- 선택지는 아래 영문 소문자 한 글자로 입력해요. 영문 입력 상태에서 왼손으로 누를 수 있는 `a/s/d/f`를 써요. 자유 서술·번호·초·횟수는 직접 입력해요. 마크다운은 텍스트 편집기의 방향키로, CSV는 편집 환경의 셀 이동 키로 채워요. 체크박스나 마우스 전용 조작은 없어요. 실제 왼손 사용 편의는 아직 확인하지 않았어요.
- 표 제목마다 CSV 머리글을 함께 두었어요. 각각 별도 표로 사용하고, 공통 키로 연결해요. CSV에서 쉼표나 줄바꿈이 든 값은 큰따옴표로 감싸고, 값 안의 큰따옴표는 두 번 적어요. 이 문서에서는 CSV 파일을 따로 만들지 않아요.
- 들은 구간은 **재생한 분석용 파일의 시작을 0초**로 삼아 시작·끝을 숫자로 적어요. A와 B의 구간은 따로 적어요. 근거 구간이 여러 개면 같은 키로 행을 더해요. 구간을 특정하지 못하면 비워 두고 이유 칸에 적어요. 빈칸은 0초나 차이 없음이 아니에요.
- 실제로 확인하지 않은 설명은 반드시 `추측:`으로 시작해요. 회사 이름·개인정보는 쓰지 않고, 위기 문항은 문장 번호로 참조해요. 해칠 방법을 떠올리게 하는 문구는 적지 않아요.

| 적용 칸 | a | s | d | f |
|---|---|---|---|---|
| 재생 순서 | AB | BA | 사용하지 않아요 | 사용하지 않아요 |
| 항목 판단·다시 들은 판단·최종 판정 | A가 내용에 더 맞게 들려요 | B가 내용에 더 맞게 들려요 | 차이 없음 | 판단 보류 |
| 확정·완료·비공개 유지·독립 작성·음량 맞춤·자동 처리 켬 | 예 | 아니요 | 확인하지 못했어요 | 해당 없어요 |
| 판단 변경 | 바뀌었어요 | 그대로예요 | 비교를 보류해요 | 사용하지 않아요 |
| 측정 상태 | 값이 있어요 | 정상 결과이지만 값이 없어요 | 일부를 제외했어요 | 파일 전체 분석에 실패했어요 |
| 평가자 간 의견 | 같아요 | 갈려요 | 아직 대조하지 않았어요 | 사용하지 않아요 |

판단 코드 `d`는 둘 다 적절하다는 뜻은 아니에요. 둘 다 맞지 않게 들려도 차이가 없으면 `d`와 그 이유를 적을 수 있어요. `f`는 구분할 근거가 부족할 때 쓰고 이유를 남겨요. 이 코드는 입력 편의를 위한 제안이며 기준표의 새 점수 체계가 아니에요.

## 3. 수치 공개와 다시 들은 판단

### 3-1. 관찰값 공개 표

운영자가 문장·항목·측정 필드마다 한 행을 채워 A/B를 나란히 보여 줘요. 관찰 번호는 시연 안에서 중복되지 않게 정해요. 수치와 사람의 판단 이유를 섞지 않아요. 값이 없는 경우 `null` 등 실제 출력을 그대로 적고, 쉼 0개 같은 유효한 0은 그대로 남겨요. 일부 제외 시 유효 결과와 `skipped`를 함께 적어요. 파일 전체 실패는 오류 원문을 적고 해당 녹음의 수치 비교를 보류해요. `skipped`가 제공되지 않는 필드는 `해당 없음`으로 적어 0과 구별해요.

| 시연 번호 | 문장 번호 | 관찰 번호 | 항목 ID | 측정 필드 | 단위 | A 측정값 | A 상태 코드 | A skipped | A 오류 원문 | B 측정값 | B 상태 코드 | B skipped | B 오류 원문 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | | | | | |

```csv
시연_번호,문장_번호,관찰_번호,항목_ID,측정_필드,단위,A_측정값,A_상태_코드,A_skipped,A_오류_원문,B_측정값,B_상태_코드,B_skipped,B_오류_원문
```

빠르기는 `perSecSpoken`만 보지 않고 발화 길이·쉼 합계·쉼 길이를 함께 놓아요. 말끝의 `count`와 `skipped`를 함께 남기고, 수치는 실제 오르내림 궤적이 아니며 마지막 덩어리를 계산하지 않는다는 v3의 한계를 설명해요. 호흡·음색과 내용과의 일치는 v3에서 재지 않는 항목이므로 측정행을 만들지 않고 재청취 표에 `측정하지 않음`이라고 적어요. 크기를 참고로 넣으면 항목 ID는 `기준표 밖`으로 적고, 음량을 맞췄다면 크기 수치를 비교에서 빼요.

## 4. 관찰과 판단 연결 기록

평가자·문장·항목마다 작성해요. 관찰값은 표 3-1의 관찰 번호로, 들은 구간은 표 3-2의 같은 키에 있는 A/B 시작·끝으로 연결해요. 추가 구간이 필요하면 표 3-2에 행을 더해요. 측정하지 않는 항목은 관찰값 칸에 `측정하지 않음`을 적어요. 다른 설명을 확인하지 못했다면 `추측:`이라고 적고, 생각나는 설명이 없으면 `확인하지 못했어요`라고 적어요. 평가자 간 대조는 각자의 기록을 마친 뒤에 해요. 의견이 갈려도 각 행을 보존하고 수치로 승자를 정하지 않아요.

## 5. 녹음별 재현 기록

운영자가 **익명 녹음 번호마다** 표 5-1·5-2를 한 행씩 작성해요. 표 1의 A/B 익명 녹음 번호로 연결해요. 녹음 파일 자체는 저장소에 올리지 않아요. 아래 경로나 명령에는 익명 상대 경로를 쓰고, 개인 계정명·회사 이름·개인정보가 들어가지 않게 해요. 실행하지 않은 명령이나 측정하지 않은 값을 실행 결과처럼 채우지 않아요.

### 5-1. 파일·분석 기록

해시는 실제 재생·분석에 쓴 파일의 SHA-256이에요. 분석 시작·끝은 자르기 전 원본의 0초 기준으로 분석 파일에 포함한 범위를 적어요. 자른 앞·뒤 길이는 원본에서 제거한 길이, 남긴 앞·뒤 여백은 분석 파일에 남아 있는 길이예요. 이렇게 나누어 두어야 같은 구간을 다시 만들 수 있어요. 편집이 단순 자르기 외에도 있으면 표 5-2에 처리 내용을 적어요. 두 코드의 커밋은 각각 적고, 작업 중 수정본이라 커밋만으로 재현할 수 없다면 그 한계도 명령·조건 칸에 남겨요.
