**측정값은 근거일 뿐 따뜻함 판정을 대신하지 않는다**는 원칙을 지켜요. 수치는 다시 들어 볼 구간을 찾는 데 쓰고, 판정은 상황과 내용을 함께 들으며 “이 목소리가 내용에 맞게 들리는가”에 한정해요. 수치로 화자나 듣는 사람의 감정·성격을 단정하지 않아요.

## 범위와 근거

G4 업무와 대표작 B에 맞춰 다섯 항목을 독립적으로 정리했어요. 대조 대상인 `docs/eval/voice-evidence.md`는 읽지 않았어요. 아래는 작업 시점의 작업 폴더 코드를 확인한 결과예요. 기존 변경분이 있어 커밋된 버전과 같다고 보장하지는 않아요.

- [대표작 계획](../FLAGSHIP.md)의 B는 초당 음절, 중요한 말 앞 쉼, 문장 끝 내림 비율, 음높이 폭, 크기 안정을 다뤄요.
- [낭독 분석 코드](../../apps/reading-coach/analysis.js)의 `envelope`, `threshold`, `speechRuns`, `analyze`, `compare`에서 구간·쉼·발화 길이 비교를 확인했어요. 이 파일 자체에는 음절 수나 음높이 측정이 없어요.
- [프로필 측정 코드](../../apps/voice-check/profile.js)의 `countSyllables`, `f0Track`, `profile`에서 음절 추정·음높이·끝음·크기 계산을 추가로 확인했어요. 말소리 구간은 위 낭독 분석 코드를 재사용해요.
- [기준표](../../apps/warmth-scorer/rubric.json)의 `voice_criteria`와 `voice_note`를 따랐어요. `pace`·`pause`는 자동 측정, `ending`·`pitch`·`breath`·`congruence`는 사람 평가로 구분돼 있어요. 자동 측정 표시가 자동 따뜻함 판정의 근거가 되지는 않아요.

대표작 계획에 적힌 기존 녹음 수치는 이번에 원본으로 재측정하지 않았어요. 따라서 목표값이나 합격선으로 옮기지 않았어요. 아래 청취 질문은 사용 제안이에요. 연구로 입증된 따뜻함의 인과관계나 보편적인 적정 수치를 주장하지 않아요.

## 모든 항목에 공통인 측정 조건

`analysis.js`는 약 20ms씩 샘플 제곱의 평균에 제곱근을 취한 RMS를 구해요. RMS의 10백분위 값을 `P10`, 90백분위 값을 `P90`이라고 하면 검출 기준은 `P10 + 0.15 × (P90 − P10)`이에요. 여기서 `P90`은 최댓값이 아니에요. `P90 < 0.01`이거나 `P90 < 3 × P10`이면 말소리를 검출하지 않아요. 기준을 초과한 상태가 80ms 이상 이어져야 말소리 구간으로 남겨요.

이 구간은 음성 인식으로 확인한 단어나 문장이 아니에요. 잡음·숨소리도 기준을 넘으면 포함될 수 있고 작은 말소리는 빠질 수 있어요. 이 영향은 쉼뿐 아니라 프로필의 다른 항목에도 이어질 수 있어요. “말소리를 찾지 못함”과 `null`은 측정 불가로 기록해요. 0점이나 “따뜻하지 않음”으로 바꾸지 않아요.

## 비교할 때 잘못 읽기 쉬운 경계

`analysis.js`의 쉼 대응은 원고의 같은 단어를 찾는 방식이 아니에요. 발화 길이에 대한 상대 위치 차이가 0.08 이하인 쉼을 시범 순서대로, 아직 쓰지 않은 가장 가까운 쉼과 연결해요. 따라서 “같은 자리” 표시는 청취로 확인할 후보예요. 연결된 쉼의 길이 차이가 **200ms 초과이면서 시범 길이의 30%도 초과**할 때 길이 안내가 나와요. 정확히 200ms 차이는 안내 대상이 아니에요. 이 수치는 구현상 안내 기준이며 따뜻함의 허용 오차가 아니에요.

`compare().score`는 시범과의 발화 길이 및 쉼 위치·개수 비교를 합친 값이에요. 쉼 길이 차이는 점수에 들어가지 않아요. 점수나 “짧게/길게 쉬어 보세요”라는 안내가 내용에 맞는 낭독 방향을 보장하지 않아요. 근거표에서는 원자료와 청취 이유를 남겨요.

기준표의 `breath`와 `congruence`는 다섯 측정 항목 밖에도 남아 있는 청취 과제예요. 이 표를 채웠다고 목소리 기준표 전체의 평가를 마쳤다고 하지 않아요.

## 대조 시연에 쓰는 방법 제안

1. 같은 문장을 두 방식으로 읽고 원고·마이크·거리·입력 이득·후처리 유무·여백 처리 조건을 기록해요. 식별에는 익명 문항 번호와 낭독 A/B만 써요.
2. 평가자 두 명 이상이 먼저 수치를 보지 않고 각각 들어 봐요. 제시 순서를 바꿔 가며 기준표 항목별 청취 이유와 구간을 독립적으로 적어요. 이 절차는 제안이며 이번에 실행하지 않았어요.
3. 이후 측정값·단위·분모·검출 실패와 제외 수를 나란히 보여 줘요. 수치가 다른 구간을 다시 듣되 처음 판단과 다시 들은 판단을 구분해서 남겨요.
4. 기록은 “관찰값 / 청취한 구간 / 내용과의 관계 / 다른 설명 가능성 / 판정 또는 보류 이유”로 나눠요. 가령 “쉼 뒤의 말을 더 편하게 들을 수 있었을 것이다”는 청취 확인 전에는 **추측**이라고 적어요. 평가자 의견이 갈리면 수치로 승자를 정하지 않아요.

이 시연으로 보여 줄 수 있는 것은 선택한 문장·녹음에서 측정 근거와 청취 판단을 연결하는 과정이에요. 보편적인 따뜻함 효과나 모든 청자의 반응을 입증했다고 쓰지 않아요.

## 이번 실행에서 확인한 것과 남은 것

Node에서 실제 `analysis.js`와 `profile.js`를 불러, 16kHz·200Hz 정현파 두 구간 사이 간격을 바꾼 합성음을 메모리에만 만들어 확인했어요. 실제 말소리나 청취자 반응 검증은 아니에요.

|---|---|
