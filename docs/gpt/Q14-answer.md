**추천 1순위는 `Eleven v4 Turbo`의 맞춤 복제 음성을 유료 API로 사용하는 방식이에요.** 내장 그래픽 PC에서도 이용할 수 있고, 한국어·목소리 복제·실시간 스트리밍·상업 사용 경로를 공식 자료에서 확인했어요. 다만 **대표 목소리의 닮음과 한국어 숫자·억양이 가장 좋다는 판단은 아직 추측이에요.** 실제 녹음으로 비교 청취해야 최종 선정할 수 있어요.

`AGENTS.md`와 `TEAM_BOARD.md`의 Q14 및 바로 위 대표 PC 확인·대표 답·대표 요청을 확인했어요. 금지하신 두 폴더는 읽지 않았고, 어떤 파일도 수정하지 않았어요. 실행 기록의 `model:`·`reasoning effort:`·`sandbox:` 원문은 제공되지 않아 그대로 옮길 수 없어요. 모델 이름을 짐작해 실행 기록으로 작성하지 않아요.

추천의 근거와 약한 부분은 다섯 가지예요.

1. **최신성과 실용성을 함께 보면 v4 Turbo를 먼저 시험할 이유가 있어요.** 2026년 9월 28일 공개됐고, 한국어·복제 음성·실시간 API를 제공해요. 대표 PC에 GPU를 추가하지 않고 검증을 시작할 수 있어요. 다만 출시 직후 모델이므로 계정에서 해당 복제 음성의 학습 완료 상태를 확인해야 해요. **추천 확실도는 중간**이에요. [출시 발표](https://elevenlabs.io/blog/eleven-v4), [복제 음성 상태 안내](https://elevenlabs.io/docs/eleven-creative/voices/voice-cloning/professional-voice-cloning)

2. **한국어 지원과 한국어 숫자 품질은 별개예요.** 조사한 자료만으로 숫자·끊어 읽기·억양의 종합 1위를 정할 수 없어요. 특히 Flash v2.5의 숫자 정규화 제한은 확인된 약점이에요. 숫자를 한글로 바꾸는 것만으로 억양까지 해결된다는 주장도 근거가 없어요. [숫자 정규화 제한](https://elevenlabs.io/docs/overview/models)

3. **목소리의 음색과 연기 재현도도 나눠 평가해야 해요.** PVC 안내는 녹음의 말투와 상태가 결과에 반영된다고 설명해요. ‘일상 대화’와 ‘CF 전달’을 한 복제 음성으로 모두 잘할지는 추측이에요. 우선 깨끗한 대화체 녹음으로 비교하고, 광고·내레이션은 별도 평가하는 편을 제안해요. [녹음 가이드](https://elevenlabs.io/docs/eleven-creative/voices/voice-cloning/professional-voice-cloning)

4. **외부 전송, 학습 사용, 보관은 서로 다른 조건이에요.** ElevenAPI는 일반 데이터 이용 설정에서 학습 사용을 끌 수 있지만, 그것이 외부 전송이나 모든 보관의 중단을 뜻하지는 않아요. Zero Retention 안내에서도 PVC는 저장이 필요한 예외로 설명돼 있어요. S2.1 무료 API 역시 요청이 모델 개선에 사용될 수 있다고 밝혀요. [데이터 이용 설정](https://elevenlabs.io/docs/help-center/legal/is-my-data-used-to-improve-eleven-labs-ai-models), [보관 예외](https://elevenlabs.io/docs/eleven-api/resources/zero-retention-mode), [S2.1 무료 조건](https://fish.audio/ko/blog/s2-1-pro-free-api/)

5. **목소리 반출을 원하지 않는다면 자체 운영의 우선 후보는 Qwen3-TTS Base예요.** 한국어 복제, 공개 가중치, 상업 사용 가능한 라이선스, 작은 모델 선택지가 근거예요. 다만 대표 PC에서 실시간 사용이 된다는 뜻은 아니에요. **자체 운영 추천은 추측이며, GPU 서버 청취 시험을 먼저 제안해요.** [공식 모델 설명](https://github.com/QwenLM/Qwen3-TTS)

음성 인식은 합성과 분리해서 골라야 해요. `whisper.cpp`와 `faster-whisper`는 서로 다른 음성 인식 모델이라기보다 **Whisper를 실행하는 서로 다른 구현**이에요.

API 방식에도 인증과 요청 제한을 처리할 작은 서버가 필요해요. **소규모 서버 월 $5~20은 견적을 받지 않은 예산 추측**이에요. 여기에 듣기 사용량, 대화 모델, 로그·저장 비용을 더해야 해요. 예를 들어 Scribe v2 Realtime 10시간은 표시 단가로 $3.90이지만, 이것만으로 비서 전체 비용을 계산할 수는 없어요.

엔진 교체는 다음처럼 구성하는 것을 제안해요. **기존 비서 코드는 읽지 않았으므로 신규 설계 제안이에요.**

`마이크 → 듣기 → 의도·작업 판단 → 허용된 작업실 도구 → 답변 문장 → 한국어 읽기 조정 → 합성 엔진 → 재생`

공통 합성 요청에는 문장·언어·목소리 식별자·취소 신호를 넣고, 엔진마다 다른 감정 태그·쉼 표시는 연결부에서 변환해요. 스트리밍 여부와 지원 기능도 연결부가 알려주게 해요. 이렇게 하면 API와 자체 모델을 바꿀 때 나머지 도구를 덜 고칠 수 있다는 판단이에요.

**교체 가능한 것은 호출 구조이고, 같은 음색·억양까지 보장되는 것은 아니에요.** 원본 녹음·전사문·읽기 사전·평가 문장을 보관하고, 엔진을 바꿀 때 다시 검수해야 해요. 외부 API 결과 음성을 다른 모델의 학습 자료로 사용하는 것도 자동 허용으로 보면 안 돼요. 예를 들어 S2 서비스 약관에는 경쟁 모델 개발에 출력을 사용하는 제한이 있어요. [관련 약관](https://fish.audio/terms/)

공개 서비스의 악용 방지는 아래처럼 제안해요. 이는 이번에 구현하거나 검사한 결과가 아니에요.

- **개인 작업실용과 공개 시연의 권한을 분리해요.** 공개 사용자가 대표 PC의 파일·터미널·작업실 도구를 직접 실행하지 못하게 해요.
- 첫 화면과 음성 안내에 **“성우 김디도의 동의를 받아 만든 AI 음성이에요.”**라고 밝혀요.
- 공개 시연은 허용된 업무와 응답 범위부터 시작해요. 임의 문장을 무제한으로 대표 목소리로 만드는 기능은 별도 권한으로 관리해요.
- API 키와 복제용 원본 녹음은 서버에 두고, 사용자별 생성량·동시 요청·월 지출 한도를 설정해요.
- 사칭·기만·무단 재배포 신고, 계정 차단, 목소리 사용 중단 기능을 마련해요. 로그에는 꼭 필요한 정보만 남겨요.
- 제공되는 워터마크는 유지하되, **워터마크나 다운로드 버튼 제거만으로 재녹음·악용을 막을 수 있다고 보지는 않아요.**

게시판의 계약 관련 대표 답은 확인했어요. 다만 계약서 원문을 검토한 것은 아니므로, 기존 녹음 파일·대본까지 모든 공개 이용 권리가 확인됐다고 확대해서 적지는 않아요.

대표의 실제 일에서는 다음 다섯 가지를 우선 제안해요. **쓸모의 순위는 업무 맥락에 근거한 추측이며, 현재 구현 여부는 확인하지 않았어요.**

| 순위 | 쓰임 | 실제 흐름과 기대 효과 |
|---|---|---|
| **1** | **작업실 도구를 말로 조작하기** | “다음 문항”, “근거 메모”, “방금 구간 다시 듣기”처럼 제한된 명령으로 채점·녹음 검수 도구를 조작해요. 왼손 조작 부담을 줄이는 데 가장 직접적일 것으로 추측해요. 음성과 함께 큰 버튼·키보드 조작도 제공해요. |

최종 선정 전에는 **같은 평가 문장 20개를 각 후보에서 생성하는 비교**를 권해요. 숫자·단위 8개, 끊어 읽기 4개, 억양 4개, 실제 작업 안내 4개로 구성하고, 원문 그대로 넣은 결과와 읽기를 조정한 결과를 나눠 봐요. 대표의 직접 녹음도 기준으로 두고 이름을 가린 상태에서 비교해요. 이 구성은 새 제안이며 기존 20문장이나 금지 폴더의 테스트는 읽지 않았어요.

**최종 추천의 확실도는 중간이에요.** 내장 그래픽 PC에서 시연과 공개 서비스를 시작하기에는 `Eleven v4 Turbo + PVC`가 우선 시험할 조합이에요. 외부 전송 없는 방향을 우선하면 `Qwen3-TTS Base`, 현재 PC에서 비용 없이 느리게라도 20문장을 만들려면 `Chatterbox Multilingual v3 CPU`를 먼저 검증하는 편을 제안해요. 어느 후보도 이번 조사에서 음성을 생성하거나 청취하지 않았어요.
