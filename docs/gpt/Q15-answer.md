**① 비교 문장 10개예요.**

[G15](/C:/Users/ddddv/dido2580/docs/gpt/G15-number-sentences.md:11)를 참고해 구성했어요. 아래 목표 읽기와 청취 포인트는 **추측을 포함한 검수 제안**이에요. 이번 실행에서 어문 규정으로 각 문장의 정답을 새로 검증하지는 않았어요. 시험 전에 목표 읽기와 허용 표현을 확정하고, 특정한 억양 곡선 하나를 정답으로 강요하지 않아요.

| 번호 | 두 모델에 똑같이 넣을 문장 | 목표 숫자 읽기 | 집중해서 들을 부분 |
|---|---|---|---|
| 01 | 시작 시각은 오후 2시 30분 5초예요. | 두 시 삼십 분 오 초 | 시·분·초가 하나의 시각으로 연결되는지, 숫자마다 억양이 새로 시작되는지 봐요. |
| 02 | 연습에 3시간 20분이 걸려요. | 세 시간 이십 분 | ‘세 시간’과 ‘이십 분’ 사이가 지나치게 벌어지거나 급하게 붙지 않는지 봐요. |
| 03 | 가상 전시는 6월 10일부터 10월 6일까지예요. | 유월 십 일부터 시월 육 일까지 | 두 날짜의 경계와 ‘부터·까지’의 연결이 명확한지 봐요. |
| 04 | 연습용 가격은 12,500원이 아니라 1,250원이에요. | 만 이천오백 원 / 천이백오십 원 | 큰 수 내부를 부자연스럽게 끊는지, 정정된 금액이 분명히 들리는지 봐요. |
| 05 | 첫 번째 값은 0.05이고, 두 번째 값은 0.5예요. | 영 점 영 오 / 영 점 오 | 소수점 뒤의 영을 보존하는지, 두 값의 구별을 억양이 돕는지 봐요. |
| 06 | 가상 설문의 응답 비율은 12.5%예요. | 십이 점 오 퍼센트 | 숫자와 단위가 한 덩어리로 들리는지, 단위 직전의 쉼이 어색한지 봐요. |
| 07 | 상자 20개와 봉투 21개를 준비해요. | 스무 개 / 스물한 개 | 물건과 수량이 올바르게 연결되고, 나열이 자연스럽게 이어지는지 봐요. |
| 08 | 제3장을 읽고, 제4장은 나중에 읽어요. | 제삼 장 / 제사 장 | 지금 읽을 장과 나중에 읽을 장의 대비가 전달되는지 봐요. |
| 09 | 연습용 상자는 2개면 충분해요. | 두 개 | 차분하게 충분하다고 알려주는 말로 들리는지 봐요. |
| 10 | 연습용 상자는 2개면 충분해요? | 두 개 | 상대에게 충분한지 확인하는 질문으로 들리는지 봐요. 무조건 끝을 높여야 한다는 기준은 두지 않아요. |

09·10은 **문장 내용은 같고 문장부호만 다른 비교**예요. 자연스럽다는 인상과 별도로, 전달된 의도를 답하게 해요. 목표 읽기의 띄어쓰기는 실제 무음 위치를 지시하지 않아요.

**② 듣는 순서는 ‘처음 듣기 → 같은 문장 짝 비교’로 나눠요.**

1. **음원을 먼저 고정해요.**  
   10문장 × 2모델 × 3회로 **60개 음원**을 만들어요. 생성 순번을 보존하고, 잘 나온 것만 고르지 않아요. 실패한 요청과 재시도도 기록해요. 평가자에게는 모델명·설정·생성 순번 대신 임의 코드를 보여줘요.

2. **원고 없이 처음 듣고 답해요.**  
   일반 청취자는 문장마다 한 모델의 음원만 들어요. 두 모델 모두 사전에 정한 첫 생성본을 사용해요. 한 번 들은 뒤 **숫자·단위·연결 대상·이해한 뜻**을 적고, 이해에 든 노력도 평가해요. “모르겠어요”를 허용하고 첫 답을 저장해요.  
   예를 들어 04는 최종 가격, 08은 지금 읽을 장, 09·10은 알림인지 질문인지 확인해요.

3. **첫 듣기 검사를 모두 마친 뒤 짝으로 비교해요.**  
   같은 문장·같은 생성 순번끼리 두 모델의 음원을 붙여 들어요. 화면에는 ‘첫째 음원·둘째 음원’으로 표시해요. **문장 순서를 섞고, 어느 모델이 먼저 나오는지도 절반씩 균형을 맞춰요.** 다음 평가자에게는 순서를 바꿔요.

4. **3회 생성분을 모두 비교해요.**  
   총 30쌍을 10쌍씩 나눠 듣고 사이에 쉬어요. 재청취 횟수는 두 음원에 같은 규칙을 적용하고 기록해요. 원고는 이 단계에서 보여줘도 되지만, 여기서 받은 답을 ‘처음 듣기 정확도’에 합치지 않아요.

5. **목소리 닮음은 별도로 확인해요.**  
   처음 듣기 검사가 끝난 뒤 성우 김디도의 실제 녹음 기준 음원을 같은 조건으로 제공해요. 자연스러움과 닮음을 각각 평가하고, 모든 응답을 확정한 다음 모델명을 공개해요.

음원 제시 순서를 균형 있게 섞는 방법과 이해 노력을 별도 평가하는 원칙은 음성 청취 평가 권고에서 참고했어요. 위 절차 전체가 해당 국제 표준을 그대로 수행하는 시험이라는 뜻은 아니에요. [음성 청취 평가 권고 원문](https://www.itu.int/rec/dologin_pub.asp?id=T-REC-P.800-199608-I!!PDF-E&lang=e&type=items)

아래 점수와 전환 경계는 **추측을 포함한 내부 운영 제안이며, 검증된 통계적 합격선은 아니에요.**

**전환 후보로 올리는 잠정 조건**은 다음처럼 시험 전에 정해둘 수 있어요.

- 새 모델의 평가 음원에서 확인된 숫자·단위·의미 오류가 없고, 첫 듣기 결과에서 기존 모델보다 나빠지는 문항이 없는지 확인해요.
- 끊어 읽기와 억양을 따로 집계해, 두 항목 모두 악화가 없고 실제 개선 구간이 있는지 확인해요.
- 각 청취자의 30쌍 평가에서 승·패를 집계하고, **24명 중 16명 이상에게 새 모델의 승수가 패수보다 많은 경우**를 선호 근거로 삼아요. 이 수치는 통계적 유의성을 뜻하지 않아요.
- 대표와 다른 검수자가 목소리 닮음의 저하를 확인하면 전환을 보류해요.
- 한 번의 좋은 생성에만 개선이 몰리거나 의견이 갈리면, 새로운 문장과 추가 생성으로 확인해요.

오류 음원 하나만으로 모델 전체가 나쁘다고 단정하지는 않아요. 다만 그 오류를 평균 자연스러움 점수로 덮어서 전환시키지도 않아요.

**④ 본 비교는 일반 청취자 24명과 검수자 2명을 권해요.**

검수자 2명에는 대표를 포함할 수 있으므로 **총 26명**이에요. 일반 청취자는 한국어에 능숙하고 원고와 생성 과정에 참여하지 않은 사람으로 구성해요.

24명을 권하는 이유는 문장별 첫 듣기를 두 모델에 반씩 배정하면 **모델마다 12명의 처음 듣기 응답**을 확보할 수 있기 때문이에요. 각 청취자는 10문장 중 기존 모델 5개·새 모델 5개를 듣고, 다른 청취자에게 배정을 뒤집어요. 이는 Q13의 초기 검수 규모 제안과 맞추기 위한 설계예요.

**24명은 통계적으로 계산한 최소 인원이 아니에요.** 필요한 표본 수는 검출하려는 차이와 응답 변동에 따라 달라지며, 아직 그 자료가 없어 충분한 인원인지는 몰라요. 같은 사람이 여러 문장을 평가한 수를 독립된 사람 수처럼 세면 안 돼요.

준비 단계에서는 대표와 다른 검수자 1명이 명백한 오류와 시험 절차를 먼저 점검할 수 있어요. 이 2명의 의견만으로 일반 청취자에게도 개선된다고 결론 내리는 것은 **추측**이에요.

| 조정 기회 | 첫 비교는 설정을 고정해요. 모델별 최적화를 비교하려면 별도 시험으로 나누고, 양쪽에 같은 조정 횟수와 시간을 줘요. |
| 생성 반복 | 모델별 3회를 모두 보존해요. 같은 시드가 두 모델에 동등한 조건을 만든다고 가정하지 않아요. |
| 음량 | 청취용 복사본의 지각 음량을 같은 측정 방법과 목표로 맞춰요. 피크만 같게 맞추는 것으로 끝내지 않아요. 클리핑 없이 고정 이득만 조정하고 원본도 보존해요. |
| 음질·재생 | 가능한 한 같은 출력 형식·샘플레이트·채널·재생 장비를 써요. 재생 속도는 1배로 고정하고, 음색 보정·잡음 제거·압축 효과는 적용하지 않아요. |
| 쉼 보존 | 문장 내부의 무음과 호흡을 자르거나 시간 길이를 늘이지 않아요. 끊어 읽기의 평가 대상이기 때문이에요. |
| 청취 환경 | 조용한 환경에서 동일한 재생 음량을 유지해요. 환경 문제로 제외할 조건은 결과를 보기 전에 정해요. |

API 문서에는 숫자 등의 텍스트 정규화 설정과 시드가 설명되어 있고, **같은 시드·설정으로도 결정적 재현이 보장되지는 않는다**고 명시되어 있어요. 각 모델과 호출 경로에서 실제 지원되는 설정은 생성 전에 확인해야 해요. [공식 음성 생성 API 문서](https://elevenlabs.io/docs/api-reference/text-to-speech/convert)

숫자를 한글로 풀어 쓴 추가 비교는 오류 원인을 좁히는 데 도움이 될 수 있어요. 다만 실제 숫자 입력 시험과 분리해서 기록해야 해요. 음질 비교를 통과한 뒤에는 실제 비서에서 응답 대기 시간과 재생 끊김도 별도로 확인해야 전환 결정을 마칠 수 있어요.
