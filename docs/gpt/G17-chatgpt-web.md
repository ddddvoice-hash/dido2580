# G17 · ChatGPT 웹에서 성우 김디도 음성 비서 부르기
> 실행 기록 머리(그대로 옮김): `model: gpt-6-astra` · `reasoning effort: high` · `sandbox: workspace-write [workdir, /tmp, $TMPDIR]` · `session id: 01a11157-8ede-7c62-94fa-7504097fcbcd`
날짜: 2026-10-06 · 브랜드: 성우 김디도 · 작성: GPT(외부 협력사) 초안, Claude 팀 검증 전

**먼저 알아두세요.** 현재 `mcp_server.py --http`에는 접근 토큰 검사가 있지만, ChatGPT의 사용자 로그인 절차에 필요한 OAuth 기능은 없어요. 공개 HTTPS 주소만 붙여서는 인증 연결이 완성되지 않아요. 먼저 사용자 인증을 담당하는 중간 서버를 준비하고, 대표 계정만 허용한 뒤 연결을 시험하는 순서를 제안해요. 이 문서는 안내 초안이며 실제 공개나 웹 연결을 완료한 기록은 아니에요.

2026-10-06에 직접 열어 본 공식 문서 본문과 현재 저장소 코드를 근거로 작성했어요. **공식 확인**, **코드 확인**, **실행 확인**, **제안**, **확인 필요**를 구분해요. 계정 화면이나 실제 배포에서 확인하지 못한 사항은 확정하지 않아요. 배포 주소·키·계정 식별자의 실제값은 싣지 않았고, 아래 링크는 공개된 공식 참고 문서예요. 제품을 찾는 데 필요한 화면 명칭 외에는 서비스 사업자 이름을 본문에 쓰지 않았어요.

**1. 웹 연결 요건을 먼저 확인해요**

| 항목 | 확인한 내용과 남은 확인 |
|---|---|
| 웹에서 추가하는 위치 | **공식 확인:** 현재 본문은 ChatGPT 웹의 `Plugins` → `+` → `Add custom MCP server` → 이름·연결·인증 설정 → `Create as a plugin`을 안내해요. 만든 뒤 설치하고 대화에서 `@`로 선택해요. [공식 연결 안내](https://developers.openai.com/api/docs/guides/custom-mcp-server) |
| 개발자 모드·커넥터 명칭 | 검색 요약에는 개발자 모드 안내가 남아 있었지만, 직접 연 현재 본문은 위의 사용자 지정 MCP 추가 절차를 안내해요. 과거의 ‘커넥터’ 메뉴나 특정 개발자 모드 스위치 위치를 현재 필수 절차로 단정하지 않아요. **확인 필요:** 대표 계정에 보이는 명칭과 개발자 모드 요구 여부예요. [공식 연결 절차 본문](https://developers.openai.com/plugins/deploy/connect-chatgpt) |
| 계정·요금제·조직 권한 | **공식 확인:** 작업공간 권한과 보안 제한이 적용되고, `Lockdown` 같은 제한도 영향을 줘요. **확인 필요:** 대표 계정의 요금제·지역·관리자 정책에서 추가가 허용되는지예요. 열람한 본문만으로 요금제별 제공 범위를 확정하지 못했어요. 메뉴가 없다는 이유만으로 구독 변경을 권하지 않아요. [공식 접근 조건](https://developers.openai.com/api/docs/guides/custom-mcp-server) |
| 통신 | **공식 확인:** 원격 연결은 SSE 또는 streaming HTTP를 지원해요. 이 서버는 Streamable HTTP의 `/mcp` 경로를 사용하므로 공개 방식에서는 유효한 인증서가 있는 HTTPS 종단점이 필요해요. PC 내부 주소를 웹 연결 칸에 그대로 넣는 방식은 아니에요. [공식 종단점 요건](https://developers.openai.com/plugins/deploy/connect-chatgpt) |
| 도구 종류 | **공식 확인:** 일반 사용자 지정 MCP는 읽기·쓰기 도구를 지원하고 `search`·`fetch`를 반드시 만들 필요는 없어요. 음성을 생성하는 `speak_as_dido`는 쓰기 작업으로 취급해요. 쓰기 호출의 기본 확인 절차를 유지해요. [공식 도구·확인 안내](https://developers.openai.com/api/docs/guides/custom-mcp-server) |

이 연결의 목표는 대화에서 음성 파일을 만드는 도구를 부르는 것이에요. ChatGPT 자체 음성 대화의 목소리를 성우 김디도 목소리로 바꾸는 기능으로 안내하지 않아요. 현재 코드의 MCP 오디오 응답이 웹에서 재생·다운로드 가능한지는 **확인 필요**예요.

**2. 지금 토큰과 웹 인증이 어떻게 다른지 확인해요**

**코드 확인:** `mcp_server.py:332–376`은 환경변수 `DIDO_MCP_TOKEN`과 요청의 `Authorization: Bearer …`가 정확히 일치해야 통과시켜요. 토큰은 16자 이상이어야 HTTP 서버가 시작되고, 인증 실패는 401이에요. OAuth 로그인·발급·갱신·사용자별 권한·인증 발견용 메타데이터는 이 파일에 구현되어 있지 않아요. 인증 없이 들어오는 모든 HTTP 경로를 막기 때문에 외부에서 메타데이터 경로만 추가한다고 해결되지도 않아요.

**공식 확인:** 웹 연결의 인증 선택지는 OAuth, 인증 없음, 혼합 방식이에요. OAuth 설정의 정적 자격 증명은 OAuth 클라이언트 등록 정보이며, 임의의 고정 Bearer 토큰을 입력하는 기능으로 해석하면 안 돼요. 공식 인증 문서는 ChatGPT가 사용자 지정 API 키를 제시할 수 없다고 명시해요. [공식 인증 선택지](https://developers.openai.com/api/docs/guides/custom-mcp-server), [공식 인증 규격](https://developers.openai.com/plugins/build/auth)

**제안:** 다음 연결 구조를 준비해요. 중간 인증 서버는 아직 구현·배포하지 않았어요.

`ChatGPT 웹 → 공개 HTTPS의 OAuth 인증 중간 서버 → 내부 전용 고정 토큰 검사 → mcp_server.py --http → 목소리 엔진`

중간 서버는 OAuth 2.1의 인증 코드·PKCE 절차, 보호 자원·인증 서버 메타데이터, 401 인증 안내를 제공해야 해요. 매 요청마다 발급자·대상 자원·만료·권한과 대표 계정 허용 여부를 검사해요. 콜백 주소는 연결 관리 화면에서 확인한 값만 인증 서버에 등록해요. [공식 인증 구현 요건](https://developers.openai.com/plugins/build/auth)

검사를 통과한 요청에만 중간 서버가 내부용 `DIDO_MCP_TOKEN`을 넣어요. 외부 요청의 인증 머리글을 그대로 내부로 전달하거나, 누구에게나 내부 토큰을 붙여 주면 안 돼요. 내부 MCP 서버는 중간 서버에서만 닿게 해요. **인증 없음으로 바꾸거나 토큰 검사를 끄는 것은 연결 해결책으로 제안하지 않아요.** 일반 웹 로그인 화면이나 터널 서비스의 별도 비밀 머리글 요구도 MCP용 OAuth와 같지 않으므로 호환 여부를 확인해야 해요.

**3. 공개 HTTPS로 여는 두 가지 방법을 비교해요**

두 방식 모두 위의 인증 중간 서버가 필요해요. 아래 비용은 비교를 위한 항목이며 결제 견적이 아니에요. 음성 생성 요금과 ChatGPT 구독료도 따로 계산해요.

| 비교 | 방법 A: 대표 PC에 고정 주소 터널 연결 | 방법 B: 원격 가상 서버로 MCP 이전 |
|---|---|---|
| 연결 경로 | 공개 HTTPS → 외부로 연결을 만드는 터널 → PC의 인증 중간 서버 → 같은 PC의 MCP예요. 공유기의 외부 수신 포트를 열지 않는 구조예요. [공식 터널 구조](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/) | 공개 HTTPS → 원격 서버의 역방향 프록시·인증 중간 서버 → 같은 서버의 MCP예요. 원본은 루프백에 두고 HTTPS 진입점만 외부에 열어요. 아래 구성은 **제안**이에요. |
| 비용 | 별도 음성 서버 임대 없이 기존 PC를 쓰지만 전기·도메인·터널 및 인증 서비스 비용이 들어갈 수 있어요. **확인 필요:** 선택한 고정 주소 상품의 무료 범위·요금·전송 한도예요. 무료 임시 터널과 운영용 고정 주소를 같은 상품으로 계산하지 않아요. | 공식 가격표에 공인 IPv4를 포함한 소형 서버 월 5달러, 메모리 0.5GB 예시가 있어요. 이는 가격 비교 기준일 뿐 합성 모델을 실행할 사양 보장이 아니에요. 도메인·저장 공간·초과 전송·인증·음성 엔진 비용이 추가될 수 있어요. [공식 가격표](https://aws.amazon.com/lightsail/pricing/) |
| 대표 PC 전원 | **켜 둬야 해요.** MCP·터널·인증 중간 서버가 실행되고 절전 상태가 아니어야 해요. 음성 엔진만 외부 서비스를 써도 MCP가 PC에 있으면 PC를 켜 둬야 해요. | MCP·인증·음성 엔진이 모두 원격에서 동작하면 **꺼도 돼요.** 원격 MCP가 대표 PC의 음성 엔진에 의존하면 PC를 계속 켜 둬야 해요. |
| 인증·보안 | 터널 자격 증명과 MCP 내부 토큰을 분리하고, 외부 진입점에서 대표 계정을 확인해요. 공개 주소를 비밀로 하는 것만으로는 보호되지 않아요. PC가 중단되면 연결도 끊겨요. | OS 보안 업데이트·인증서 갱신·접근 권한·비밀 저장소·비용 차단을 운영해야 해요. 원본 포트를 우회해 직접 부를 수 없게 방화벽을 설정해요. |
| 목소리 자료 | 로컬 엔진이면 참고 녹음을 PC에 둘 수 있어요. 외부 음성 엔진을 선택하면 읽을 글이 그 엔진으로 전송돼요. | 로컬 합성 모델을 원격으로 옮긴다면 참고 녹음·모델 저장 공간과 처리 성능이 필요해요. 외부 음성 엔진을 이용하면 그 엔진용 비밀 자격 증명을 원격에서 보호해야 해요. |
| 적합한 사용 | 대표 혼자 짧게 시험하는 구성으로 제안해요. | 대표 PC가 꺼져 있을 때도 계속 쓰려는 구성으로 제안해요. 실제 필요한 메모리·처리 시간은 **확인 필요**예요. |

**방법 A의 준비 순서예요.** 담당자가 PC 안에서 인증 중간 서버와 MCP를 먼저 연결해요. 터널 관리 화면에서 고정 HTTPS 호스트를 만들고, 연결 대상을 인증 중간 서버로 지정해요. 인증 메타데이터·콜백 경로와 `/mcp` 전달 규칙을 설정해요. 터널은 PC에서 밖으로 연결하게 하고, 외부에서 인증 없는 요청이 거절되는지 확인한 뒤 웹에 등록해요. 공개 주소가 MCP 원본을 직접 가리키게 설정하지 않아요.

빠른 임시 터널은 운영용 대안으로 권하지 않아요. 공식 문서에 주소 변경, 가동 보장 없음, 동시 요청 200개, SSE 미지원 제약이 있어요. Streamable HTTP도 응답에 SSE를 사용할 수 있으므로 이름에 HTTP가 있다는 이유로 호환을 확정하면 안 돼요. **확인 필요:** 선택한 고정 터널의 실제 MCP 스트리밍 동작이에요. [공식 임시 터널 제약](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

**방법 B의 준비 순서예요.** 담당자가 원격 서버에 실행 환경과 비밀 저장소를 준비해요. MCP는 같은 서버의 루프백에서 실행하고, HTTPS 프록시·인증 중간 서버를 앞에 둬요. 도메인 연결과 인증서 자동 갱신, 프로세스 재시작, 출력·캐시 보관 한도를 설정해요. 원격 서버에서 목소리 엔진을 사용할 수 있는지 확인하고, PC를 꺼도 호출되는지 별도로 시험해요. 현재 코드는 포트만 바꿀 수 있고 루프백 바인딩을 유지하므로, 별도 컨테이너에서 접근하려면 네트워크 배치 검토가 필요해요.

**두 방식 공통 확인 필요:** 설치된 MCP 라이브러리 버전, 공개 호스트의 Host·Origin 검사, 초기화와 도구 목록 조회, 스트리밍 전달, 연결 제한 시간, 프록시 응답 크기 한도예요. 보안 검사를 끄는 대신 프록시와 원본의 허용 호스트 설정을 맞춰요.

**공개가 필요 없다면 별도 선택지도 있어요.** 공식 `Secure MCP Tunnel`은 외부 수신 포트 없이 비공개 MCP를 연결하는 방식이에요. 위 두 공개 HTTPS 방식과 구분해요. 터널 식별자·실행용 API 키·터널 생성/사용 권한·대상 작업공간 연결이 필요하고 클라이언트를 계속 실행해야 해요. **확인 필요:** 대표 계정의 제공 여부·가격·현재 `TokenGate`에 대한 HTTP 인증 전달 설정이에요. 인증 전달을 확인하지 않고 기존 `--http`가 그대로 연결된다고 쓰지 않아요. 공개 배포용 플러그인 제출을 대체하는 방식도 아니에요. [공식 비공개 터널 안내](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)

**5. 담당자 준비가 끝난 뒤 대표가 진행할 순서예요**

1. 담당자가 인증 중간 서버와 내부 토큰 주입, 목소리 엔진을 준비해요. 처음에는 대표 계정만 허용해요. 아래 명령은 기존 환경변수에 내부 토큰이 안전하게 준비되어 있을 때만 서버를 시작해요. 토큰 실제값을 입력·출력하지 않아요. 필요한 Python·MCP 실행 환경의 설치는 별도 준비 사항이에요.

```powershell
Set-Location -LiteralPath ~/dido2580; if ($?) { if ([string]::IsNullOrWhiteSpace($env:DIDO_MCP_TOKEN) -or $env:DIDO_MCP_TOKEN.Length -lt 16) { throw '담당자가 내부 접근 토큰을 안전하게 준비한 뒤 실행해 주세요.' }; python -B apps/dido-assistant/mcp_server.py --http }
```

2. 이 창은 서버 실행 중 켜 둬요. 끝낼 때는 `Ctrl+C`를 눌러요. 방법 A는 담당자가 준비한 고정 터널도 실행되어 있어야 해요. 위 명령만으로 공개 HTTPS나 OAuth가 생기지는 않아요. 방법 B에서는 같은 역할의 프로세스를 원격 서버에서 관리해요.
3. ChatGPT 웹의 플러그인 추가 화면에서 이름을 **성우 김디도 음성 비서**로 적어요. 연결 주소에는 담당자가 검증한 HTTPS 주소의 `/mcp` 경로를 넣고, 인증은 준비한 OAuth를 선택해요. 내부 MCP 토큰이나 음성 엔진 키를 OAuth 클라이언트 비밀 칸에 넣지 않아요.
4. 대표 계정으로 로그인하고, 표시되는 권한과 주의 문구를 확인해요. 생성·설치 후 네 도구 `dido_voice_status`, `read_numbers_like_dido`, `check_script_numbers`, `speak_as_dido`가 보이는지 확인해요. 없으면 연결 세부 화면에서 인증·초기화 오류를 먼저 확인해요. [공식 연결·설치 절차](https://developers.openai.com/plugins/deploy/connect-chatgpt)
5. 새 대화에서 `@`로 **성우 김디도 음성 비서**를 선택하고 먼저 “현재 목소리 준비 상태만 알려 주세요. 소리는 만들지 마세요.”라고 요청해요. 다음에는 “오전 9시 30분을 읽는 말로 바꿔 주세요. 소리는 만들지 마세요.”로 글 반환만 확인해요.
6. 준비가 확인되면 “성우 김디도 목소리로 ‘안녕하세요. 오늘도 반가워요.’를 한 번만 만들어 주세요. AI로 만든 음성임을 표시해 주세요.”라고 요청해요. 담당자는 `speak_as_dido`의 `play=false`, `return_audio=true`와 실제 생성 문장을 확인해요. 준비 중이면 재시도를 멈추고 작업 상태를 확인해요.
7. 결과의 성공 표시뿐 아니라 웹의 실제 재생·다운로드와 AI 표시를 확인해요. 키보드의 `Tab`·`Shift+Tab`·`Enter`로 추가·선택·승인·재생까지 가능한지 확인해요. 한 손 사용 편의와 포커스 이동은 **확인 필요**예요. 확인하지 않은 단축키는 안내하지 않아요.

**소리가 안 나면 이렇게 구분해요.** HTTP 모드에서는 서버 스피커 재생을 끄고 기본적으로 소리 바이트를 응답에 붙여요(`mcp_server.py:233–287`). 원본 소리가 3MiB를 넘으면 첨부하지 않으며, Base64 전송 크기는 원본보다 커져요. `ok=true`여도 `audio_included=false`이면 웹에 소리가 전달된 것이 아니에요. `result_id`는 다운로드 주소가 아니고 현재 파일에는 이를 공개 다운로드로 바꾸는 경로가 없어요. 또한 오디오 형식을 만드는 라이브러리 기능이 없으면 첨부 응답을 만들지 못할 수 있어요. 웹이 MCP `AudioContent`를 어떻게 표시하는지도 **확인 필요**예요. 필요하면 별도 인증된 재생 UI나 짧은 수명의 다운로드 경로를 후속 업무로 설계해요.

아래는 담당자가 실제 연결 환경에서 확인해야 할 항목이며, 이번 실행에서 통과했다고 표시하지 않아요.

|---|---|
| 인증 없는 요청·만료된 로그인·허용하지 않은 계정 | 합성 전에 거절하고 비용이 발생하지 않아야 해요. 인증 발견용 공개 메타데이터는 비밀 없이 정상 조회되어야 해요. |
| 재시작·여러 프로세스·동시 요청 | 사용자별·전체 사용량과 비용 한도가 유지되어야 해요. 현재 메모리 한도만으로는 만족하지 못해요. |

**실행 확인:** 소스의 `_env_int`, `RateLimit`, `TokenGate`만 구문 트리에서 추출해 메모리 안에서 10개 단언을 실행했고 모두 통과했어요. 분당 차단, 최근 24시간 차단과 만료, 새 제한 객체에서 기록이 초기화되는 동작, 0 설정이 1로 바뀌는 동작, 토큰 없음·오류의 401, 일치 토큰 통과, WebSocket 거절을 확인했어요. 전체 앱이나 실제 HTTP 통신 시험은 아니에요. 첫 시도는 명령 인용 문제로 구문 오류가 났고, 표준입력 전달로 고친 뒤 통과했어요. 시험 파일·캐시·음성 파일을 만들지 않았어요.
